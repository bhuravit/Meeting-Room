# ระบบจองห้องประชุม

หน้าเว็บหน้าเดียว (`index.html`) สำหรับจองห้องประชุม 2 อาคาร มีตารางรายวัน แบบฟอร์มจอง ตรวจเวลาซ้ำ ขั้นตอนอนุมัติ และหน้าผู้ดูแล

## ฟีเจอร์

- ตารางรายวัน 07:00–21:00 ช่วงละ 30 นาที แยกตามอาคารและห้อง คลิกช่องว่างเพื่อเลือกเวลา (เวลาสิ้นสุดตั้งไว้เบื้องต้น +1 ชั่วโมง)
- สลับมุมมอง รายวัน / รายสัปดาห์ / รายเดือน (สัปดาห์เริ่มวันอาทิตย์) คลิกวันที่เพื่อไปมุมมองรายวัน
- คลิกบล็อกการจองเพื่อดูรายละเอียด สีของบล็อกแยกตามหน่วยงาน (7 ฝ่าย และ 6 สาขาวิชา)
- แบบฟอร์มจอง: หัวข้อ รายละเอียด จำนวนผู้เข้าร่วม อาหารเครื่องดื่ม อุปกรณ์ (PC, Notebook, LCD Projector, เครื่องฉายภาพ 3 มิติ, ระบบเสียง, Online)
- ตรวจเวลาซ้ำในห้องเดียวกัน และตรวจจำนวนคนไม่ให้เกินที่นั่ง
- ผู้ดูแลอนุมัติ ไม่อนุมัติ หรือยกเลิกได้จากรายละเอียดการจองในตารางโดยตรง (คลิกบล็อกการจอง) และมีแถบแจ้งจำนวนคำขอที่รออนุมัติ
- นำเข้าผู้ใช้หลายคนจากไฟล์ Excel/CSV (หัวคอลัมน์: ชื่อ-นามสกุล, หน่วยงาน, อีเมล, รหัสผ่าน, ผู้ดูแล) มีไฟล์ตัวอย่างให้ดาวน์โหลดในหน้าผู้ดูแล
- หน้าผู้ดูแล (`#admin`): เพิ่ม ลบ แก้ไขอาคาร ห้อง จำนวนที่นั่ง และจัดการผู้ใช้ (เพิ่มผู้ใช้ แก้ไขชื่อ หน่วยงาน อีเมล รหัสผ่าน ตั้ง/ยกเลิกสิทธิ์ผู้ดูแล ลบผู้ใช้) ผ่าน Edge Function `manage-users` ที่ตรวจสิทธิ์ผู้ดูแลฝั่งเซิร์ฟเวอร์
- รายงานสรุปการใช้งานรายเดือนและรายปี (หน้าผู้ดูแล → รายงานสรุปการใช้งาน): จำนวนการจอง ชั่วโมงใช้งาน แยกตามวัน/เดือน ห้อง หน่วยงาน และผู้จอง นับเฉพาะรายการที่อนุมัติ พร้อมดาวน์โหลด CSV
- รองรับโหมดสว่างและมืด ใช้งานบนมือถือได้

## การทำงานของข้อมูล (Supabase)

ใช้ Supabase เป็นฐานข้อมูลและระบบล็อกอิน จึงนำขึ้น Vercel / GitHub Pages ได้โดยไม่ต้องมีเซิร์ฟเวอร์ของตัวเอง

- เข้าสู่ระบบด้วย **อีเมล + รหัสผ่าน** (Supabase Auth) ไม่มีการสมัครเองในหน้าเว็บ ผู้ดูแลเพิ่มผู้ใช้จากหน้าผู้ดูแล และควรปิด "Allow new users to sign up" ใน Supabase (Authentication → Sign In / Providers) เพื่อไม่ให้สมัครผ่าน API ได้
- เปิดเว็บแล้วเห็นตารางห้องประชุมทันทีโดยไม่ต้องล็อกอิน (ดูได้อย่างเดียว) จะให้เข้าสู่ระบบเมื่อคลิกช่องว่างเพื่อจอง แล้วพาไปฟอร์มจองพร้อมห้องและเวลาที่เลือก ผู้ชมที่ไม่ล็อกอินเห็นรายละเอียดการจอง (หัวข้อ ผู้จอง หน่วยงาน) แต่ไม่เห็น `created_by`
- ในโค้ดมีเฉพาะ URL และ publishable key ซึ่งเปิดเผยได้ สิทธิ์ทั้งหมดบังคับที่ฐานข้อมูลด้วย Row Level Security
- ข้อมูลอัปเดตแบบเรียลไทม์ (Realtime)
- ปุ่ม "ลองโหมดทดลอง" ใช้ข้อมูลตัวอย่างในหน้าเว็บ ไม่บันทึกลงฐานข้อมูล

| ตาราง | เนื้อหา | สิทธิ์เขียน |
|---|---|---|
| `bookings` | คำขอจอง | ผู้ล็อกอินเพิ่มได้ในชื่อตัวเอง เจ้าของยกเลิกได้ (แก้ได้เฉพาะ `cancelled`) |
| `decisions` | ผลอนุมัติ (`approved`, `rejected`, `cancelled`) | ผู้ดูแลเท่านั้น |
| `venues_config` | รายชื่ออาคารและห้อง (แถวเดียว) | ผู้ดูแลเท่านั้น |
| `admins` | รายชื่อผู้ดูแล | แก้ผ่าน SQL เท่านั้น |
| `allowed_email_domains` | โดเมนอีเมลที่สมัครได้ | แก้ผ่าน SQL เท่านั้น |

ฐานข้อมูลมีตัวกันเวลาจองซ้ำ (trigger) คำขอที่ยังไม่มีรายการใน `decisions` ถือว่า "รอการอนุมัติ"

### ตั้งผู้ดูแลคนแรก

สมัครและยืนยันอีเมลก่อน แล้วรันใน Supabase → SQL Editor

```sql
insert into public.admins (user_id)
select id from auth.users where email = 'อีเมลผู้ดูแล@โดเมน';
```

เพิ่มโดเมนที่สมัครได้: `insert into public.allowed_email_domains values ('example.ac.th');`

### ตั้งค่าที่แนะนำใน Supabase

Authentication → URL Configuration: ใส่ URL ของเว็บ (เช่นโดเมน Vercel) ใน Site URL และ Redirect URLs เพื่อให้ลิงก์ยืนยันอีเมลกลับมาที่เว็บถูกต้อง

## ปรับแต่ง

ค่าเริ่มต้นอยู่ต้นสคริปต์ใน `index.html`

- `DEFAULT_B`: อาคารและห้อง (ผู้ดูแลแก้ไขจากหน้าผู้ดูแลได้)
- `UNITS`: รายชื่อหน่วยงานและสีประจำหน่วย
- `BCOL`: สีประจำอาคาร
- `N`: จำนวนช่วงเวลา 30 นาที เริ่มที่ 07:00 (ค่าเดิม 28 ช่วง สิ้นสุด 21:00)
